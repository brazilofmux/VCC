The Tandy Color Computer 3 now runs at 640 MIPS.

Some context for that number.

My RISC-V binary translator hits 9.3 BIPS. My Z80 translator hits 4.3 BIPS — and the Z80 fights you the whole way. So why does the CoCo "only" hit 640 MIPS?

Because this one isn't a CPU translator. It's the whole computer — the GIME video chip drawing every scanline, the interrupt latch clocking like the real silicon, the floppy controller spinning virtual disks, the keyboard matrix scanning at 60Hz. Every emulated instruction carries the entire machine on its back. It twists the problem into a completely different shape: the CPU work is nearly free, and the fight is against the metronome.

The stock CoCo 3 ran at 0.894 MHz — about 0.2 MIPS. This one runs the same instruction stream at ~3200× realtime on an M5 Max: a 2.9 GHz 6809, give or take.

My favorite moment along the way: Microsoft deliberately overlapped instructions in the BASIC ROMs to save bytes — the same bytes decode as different instructions depending on where you jump in. Anyone who read the ROM disassembly articles back in the 80s knew this. I've known it for forty years. And then it reached across those forty years and broke my JIT's code-cache invalidation, and I had to redesign around a size optimization someone at Microsoft made before some of my tools' languages existed. Respect.

For historical flavor: export regulations once treated the 1-MIPS VAX as strategically sensitive computing power. By that math, this Radio Shack computer now requires roughly 640 export licenses.

And it's correct first — every optimization survives byte-for-byte differential testing against the reference interpreter, booting NitrOS-9 Level 2 and running BASIC09. It pastes from the Mac clipboard. It compiles C from the command line.  It has a Dock icon.

1979 would like a word.
